## 3. 발견 사항

### 3-1. 브랜치 상태 (`agy/design` 고유 문제)

- **피드백 폼이 아무것도 보내지 않습니다.** `frontend/src/components/FeedbackModal.tsx:24-33`의 제출 처리는 화면에 "소중한 의견이 접수되었습니다!"를 띄우고 1.8초 뒤 창을 닫을 뿐입니다. 전송 코드가 없습니다. `main`은 이 문제를 GitHub Issues 연결로 이미 고쳤습니다 (`2c9ea95`).
- **임시 메일 주소가 사용자에게 보입니다.** `frontend/src/constants/links.ts:22`의 `DEV_EMAIL = 'contact@example.com'`이 피드백 창에 표시되고 복사 단추로 복사됩니다.
- **쓰이지 않는 코드와 패키지가 남아 있습니다.**
  - `DemographicsChart.tsx`는 백엔드가 `demographics`를 한 번도 채우지 않아 화면에 나오지 않습니다.
  - `clsx`, `tailwind-merge`는 소스 어디에서도 가져오지 않습니다.
  - `BUY_ME_A_COFFEE_URL`은 쓰는 곳이 없습니다.
- **원인:** `agy/design`이 `main`의 마지막 커밋 1건(`2c9ea95`)보다 먼저 갈라져 나왔고 그 뒤로 합쳐지지 않았습니다. 지금 상태로 `agy/design`을 `main`에 합치면 위 문제들이 공개 페이지로 되돌아갑니다.

### 3-2. 공개 페이지

- **접속하면 항상 오류가 뜹니다.** `App.tsx:54-56`이 첫 화면에서 '선크림'을 자동 조회합니다. GitHub Pages에는 데이터 서버가 없어서 `/api/trend/…`가 404 HTML을 돌려주고, 화면에는 "분석 처리 오류: 데이터 서버가 연결되어 있지 않아…"가 표시됩니다. 실측: `greycity1988.github.io/api/trend/선크림` → 404.
- **스위트 메뉴 링크 3개가 열리지 않습니다** (`constants/links.ts:6-16`).
  - CAL: `greycity1988.github.io/competitive-ad-lens/` → 404
  - BEP Master: `greycity1988.github.io/bep-master/` → 404
  - FatigueRadar & StatWinner: 배포 주소가 `http://localhost:5177`입니다. 방문자 PC의 로컬 주소로 이동합니다.
- **검색·공유 정보가 없습니다.** `index.html`에 description과 OG 태그가 없습니다.
- **외부 글꼴을 두 곳에서 불러옵니다** (Google Fonts, jsDelivr). 개인정보처리방침에는 이 내용이 없습니다.

### 3-3. 데이터 정확도 (백엔드)

- **구글 변화율이 구조적으로 하락으로 나옵니다.** `services/google.py:21-24`는 마지막 두 지점을 비교하는데, 구글 트렌드의 마지막 지점은 아직 끝나지 않은 주입니다. 네이버 쪽은 같은 이유로 진행 중인 달을 일부러 뺐습니다 (`services/naver.py:51-55`). 구글에는 같은 처리가 없습니다.
- **기간이 다른 변화율을 한데 묶어 판정합니다.** 네이버는 전월 대비, 구글은 전주 대비인데 둘 다 `weekly_change_pct`에 담기고, `main.py:126-134`가 이 둘로 "상승 / 하락 / 혼조"를 정합니다.
- **채널마다 마지막 달이 다릅니다.** 네이버는 지난달까지, 구글은 이번 달까지 들어와서 통합 차트의 마지막 지점은 구글 값만 있습니다 (`main.py:77-87`).
- **인스타그램은 항상 예시 데이터입니다.** `fetch_meta_trend`는 네트워크 호출을 하지 않습니다 (`services/meta.py:85-86`). 그런데 기본 설정에 포함돼 있어 차트에 항상 가짜 선이 하나 그려집니다 (`config.py:29`). 핀터레스트는 같은 이유로 기본에서 빠져 있습니다.
- **네이버 인증 정보를 두 서버로 보냅니다.** 같은 Client ID와 Secret을 `naverapihub.apigw.ntruss.com`에 먼저 보내고, 실패하면 `openapi.naver.com`에 보냅니다 (`services/naver.py:67-95`). 첫 번째 주소가 실제로 운영되는 공식 주소인지 이번 점검에서 확인하지 못했습니다.
- **구글 수집 경로가 불안정합니다.** `pytrends`는 비공식 라이브러리이고 구글이 요청을 자주 차단합니다. 차단되면 조용히 예시 데이터로 넘어갑니다. 화면에는 예시로 표시되지만 운영자는 실패를 알 수 없습니다.

### 3-4. 문서와 실제의 차이

- **README가 구현되지 않은 기능을 설명합니다.** "월간 추정 쿼리 건수(PC/MO 비중)", "성별/연령대 탐색 비중", "해시태그 누적 피드 수", "선행 시즈널 피크 구간 예측"은 코드에 없습니다. 배지의 Vite 5.4도 실제 6.4와 다릅니다.
- **사용 안내도 같습니다.** `GuideModal.tsx:128`은 "연령·성별 오디언스 프로필을 확인합니다"라고 안내하고, 제목은 "4대 채널 통합 조회"입니다. 실제 수집 채널은 네이버와 구글 2개입니다.
- **로딩 문구가 사실과 다릅니다.** `App.tsx:99` "네이버, 구글, 인스타그램 트렌드 수집 및 지수화 중". 인스타그램은 수집하지 않습니다.

### 3-5. 프런트엔드 코드

- **연속 검색 시 결과가 뒤바뀔 수 있습니다.** `App.tsx:28-52`에 요청 취소가 없어 먼저 보낸 요청이 늦게 도착하면 최신 결과를 덮어씁니다. 시간 제한도 없습니다.
- **번들이 큽니다.** 차트 라이브러리(recharts)가 한 덩어리에 들어가 JS가 635KB입니다.
- **접근성이 거의 없습니다.** 컴포넌트 12개에서 `aria-`·`role` 속성이 1개입니다. Esc 닫기는 스위트 메뉴에만 있고 나머지 모달 3개에는 없습니다. 9~11px 글자가 46곳입니다.
- **스위트 메뉴가 저장소마다 복사돼 있습니다.** ACV와 OTT에 `SuiteNavigationDrawer.tsx`가 따로 있어 문구와 링크를 두 곳에서 고쳐야 합니다.
- **자동화가 없습니다.** CI 설정, ESLint 설정, 프런트 테스트가 없습니다.

## 4. 잘 된 점

- **예시 데이터를 숨기지 않습니다.** 채널별 `is_live` 값으로 카드에 "MOCK PREVIEW", 차트에 점선과 "(예시)", 연관 키워드에 "실제 / 예시"를 구분해 표시합니다. 요약 문장도 실제 데이터 채널만으로 만듭니다 (`main.py:118-154`).
- **입력과 요청을 막아 둡니다.** 키워드 40자 제한, 제어 문자 차단, 클라이언트당 분당 10회 제한, 10분 캐시가 있습니다 (`main.py:29-75`).
- **백엔드가 기본으로 이 PC에서만 열립니다.** `HOST` 기본값이 `127.0.0.1`이고 CORS는 지정한 주소와 GET만 허용합니다 (`config.py:13-22`).
- **토큰이 주소나 로그에 남지 않습니다.** Meta 토큰은 Authorization 헤더로만 보내고, 오류 로그에는 예외 종류만 남깁니다 (`services/meta.py:26-28,79-82`).
- **배포 스크립트가 안전합니다.** 깨끗한 작업 폴더에서만 빌드하고, 웹 파일 외의 파일이나 토큰 모양 문자열이 있으면 중단하며, 기본 동작이 시험 실행입니다 (`scripts/deploy_pages.sh`).
- **후원 창에 개인정보가 없습니다.** Ko-fi 링크만 씁니다.
- **의존성 버전이 고정돼 있습니다** (`backend/requirements.txt`).
